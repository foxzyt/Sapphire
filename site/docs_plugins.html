Criando Plugins com o Spark

O Spark é o gerenciador de pacotes e projetos oficial da linguagem Sapphire. Com ele, você pode não apenas baixar bibliotecas prontas feitas pela comunidade, mas também criar os seus próprios Plugins e módulos compartilháveis de maneira simples e elegante.

Seja para dividir o seu código em partes menores ou publicar um módulo na web, o Spark cuida de tudo para você, como uma experiência análoga ao Cargo no Rust ou o NPM no Node.js.

Estrutura de um Projeto

Tudo começa com o arquivo de manifesto sapphire.json. Este arquivo descreve as informações do seu plugin, versão, dependências e quem é você.

Terminal 
$ spark init
Name: meu_plugin
Author: Seu Nome
Description: Um plugin incrível
Version: 1.0.0

Isso gerará a seguinte estrutura de pastas:

meu_plugin/
├── sapphire.json      (O manifesto e dependências)
├── PLUGIN.txt         (Usado internamente pelo ecossistema)
├── src/
│   └── main.sp        (Arquivo de entrada opcional)
└── tests/             (Onde os testes unitários residem)

Comandos do Spark

O Spark possui várias ferramentas embarcadas que agilizam o seu trabalho no dia-a-dia:

  • spark init: Inicia um novo projeto (como no exemplo acima).
  • spark install <repo/nome>: Baixa um plugin do GitHub (ex: foxzyt/sapphire-json).
  • spark install --save-dev <repo/nome>: Instala uma dependência mas apenas para ambiente de desenvolvimento.
  • spark purge: Desinstala e limpa plugins que não estão mais sendo utilizados.
  • spark test [dir]: Varre a pasta de testes e executa suas rotinas.
  • spark clean: Remove artefatos temporários do projeto.

Quirks e Comportamentos (Global vs Local)

O Spark possui um comportamento de resolução duplo quando busca por plugins (o famoso Bug de Escopo resolvido). O escopo divide-se em Global e Local:

  • Local: Fica na pasta ./plugins/ dentro do seu projeto atual. Tem precedência máxima.
  • Global: Fica na pasta %AppData%\Sapphire\plugins (Windows) ou equivalente em outros SOs. É usado de forma secundária.

Se o Spark encontrar o mesmo plugin nas duas pastas, a versão Local sempre vence. Portanto, usar `--save-dev` ou focar no escopo local é ótimo para evitar conflitos de versão entre múltiplos projetos na sua máquina!

Testes Automatizados

Você pode testar seus módulos nativamente com o Spark sem precisar de nenhuma biblioteca extra! Basta criar a pasta tests/ (ou qualquer pasta e passa-la como argumento: spark test minha_pasta/) e colocar seus scripts `.sp` lá dentro.

Você pode criar um arquivo chamado SparkTestConfig.txt para forçar o Spark a avaliar a saída do seu script em vez de apenas o código de término (Exit Code). O layout é simples:

SparkTestConfig.txt 
[math_test.sp]
EXPECT: SUCESSO

[network_test.sp]
EXPECT: HTTP 200

No seu arquivo math_test.sp, você então executa a lógica e imprime a palavra de sucesso esperada:

sapphire 
var resultado = 10 + 20;
if (resultado == 30) {
    print("SUCESSO");
} else {
    print("FALHA");
}

Rodando spark test, o terminal lhe dirá exatamente quais testes passaram e quais falharam! ✅

Módulos Nativos (C-API)

Além de escrever bibliotecas inteiramente em Sapphire, o Spark suporta empacotamento de DLLs e Shared Objects (arquivos .so no Linux/macOS) que expandem a linguagem com código nativo C++.

Uma função de extensão em C++ requer a assinatura SapphireValue native_func(int argCount, SapphireValue* args). O ecossistema agora usa a arquitetura Tagged Union para velocidade extrema.

C++ 
#include "sapphire_plugin.h"

// Recebe dois números e retorna a soma como um Valor Nativo
SapphireValue native_soma(int argCount, SapphireValue* args) {
    if (argCount != 2 || args[0].type != ValType::NUMBER || args[1].type != ValType::NUMBER) {
        return create_nil_value();
    }
    
    double a = args[0].as.number;
    double b = args[1].as.number;
    
    SapphireValue result;
    result.type = ValType::NUMBER;
    result.as.number = a + b;
    
    return result;
}

// Registro no módulo
extern "C" void register_plugin(PluginContext* ctx) {
    ctx->define_native("soma_nativa", native_soma);
}

E no seu código Sapphire, o módulo pode ser carregado magicamente pelo interpretador:

sapphire 
var lib = import("meu_plugin_nativo");
print(lib.soma_nativa(10, 50)); // Imprime 60
