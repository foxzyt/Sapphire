Exceptions Handling

📖 What You Will Learn in This Chapter:
  • What exceptions are and why programs crash
  • How to catch errors with try/catch to prevent crashes
  • How to throw your own custom errors
  • How to use finally for cleanup code that always runs
  • How to build robust applications that handle failures gracefully

Errors happen. The network might drop, a file might be missing, or a user might enter invalid input. If left unhandled, an error crashes the Sapphire Virtual Machine. To build resilient applications, you must use Exception Handling.

What Are Exceptions?

An exception is an event that disrupts the normal flow of your program. When something goes wrong (like dividing by zero or trying to read a file that doesn't exist), Sapphire "throws" an exception. If you don't catch it, the program stops entirely.

Think of it like a fire alarm: something went wrong (the alarm goes off / an exception is thrown), and you need to handle it (evacuate / catch the exception) before continuing with your day.

Try and Catch

The try / catch block allows you to "attempt" to run dangerous code. If that code throws an error, the VM immediately aborts the try block and jumps into the catch block without crashing the entire program.

sapphire 
print("Testing handled exception...");

try {
    print("Inside try block");
    throw "Deu ruim!";
    print("This should not be printed");
} catch (e) {
    print("Caught an exception!");
    print(e);
}

print("After try/catch block");
> Testing handled exception...
> Inside try block
> Caught an exception!
> Deu ruim!
> After try/catch block
💡 Note: The line print("This should not be printed") never executes because throw immediately jumps to the catch block. This is how exceptions work — they interrupt the normal flow.

Throwing Custom Exceptions

You are not limited to catching VM errors. You can also throw your own custom errors using the throw keyword. This is extremely useful for input validation in functions. You can throw strings, numbers, or any value.

sapphire 
function setAge(age) {
    if (age < 0) {
        throw "Age cannot be negative!";
    }
    print("Age set to: " + age);
}

try {
    setAge(-5);
} catch (err) {
    print("Validation Failed: " + err);
}

// You can throw numbers too
function foo() {
    throw 404;
}

try {
    foo();
} catch (err) {
    print("Error code: " + err);
}
> Validation Failed: Age cannot be negative!
> Error code: 404

Using Finally

Sometimes you need to ensure that certain cleanup code runs whether an error occurred or not (e.g., closing an open file or a database connection). The finally block executes after try and catch, regardless of the outcome. Even if no exception was thrown, the finally block still runs.

sapphire 
print("Case 1: No exception");
try {
    print("  Inside try");
} catch (e) {
    print("  Inside catch: this should not print");
} finally {
    print("  Inside finally: this should print!");
}

print("---");

print("Case 2: With exception");
try {
    print("  Inside try 2");
    throw "Oops!";
} catch (e) {
    print("  Inside catch 2: ");
    print(e);
} finally {
    print("  Inside finally 2: this should print!");
}

print("Done!");
> Case 1: No exception
> Inside try
> Inside finally: this should print!
> ---
> Case 2: With exception
> Inside try 2
> Inside catch 2:
> Oops!
> Inside finally 2: this should print!
> Done!
💡 Important: The finally block runs regardless of whether an exception was thrown or caught. Use it for cleanup operations like closing files, database connections, or releasing resources.

Real-World Example: Safe File Reader

Here's a practical example that combines everything we've learned into a robust file-reading function.

sapphire 
function safeReadFile(path) {
    try {
        print("Opening file: " + path);
        var content = readFile(path);
        print("File read successfully!");
        return content;
    } catch (e) {
        print("Error reading file: " + e);
        return nil;
    } finally {
        print("Cleanup: file handle closed.");
    }
}

var data = safeReadFile("config.json");
if (data != nil) {
    print("Data length: " + len(data));
} else {
    print("Using default configuration.");
}
> Opening file: config.json
> Error reading file: File not found
> Cleanup: file handle closed.
> Using default configuration.

Overview — What You Learned

✅ Chapter Summary:
  • Exceptions are errors that disrupt normal program flow
  • try/catch catches errors and prevents crashes: try { risky } catch (e) { handle }
  • throw creates your own errors: throw "error message" or throw 404
  • finally runs cleanup code no matter what — even if no error occurred
  • Always use try/catch around file operations, network requests, and user input validation
  • Check for nil returns after a caught error to handle failures gracefully
