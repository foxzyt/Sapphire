Multi-threading

While async/await is perfect for I/O bound tasks (like waiting for the network), it still runs on a single thread. If you need to perform heavy mathematical calculations (CPU-bound tasks), you need true concurrency. Sapphire provides access to OS-level threads via the Thread class.

Creating and Spawning Threads

You can spawn a new thread by passing a function into Thread.spawn(). The Virtual Machine will immediately schedule this function to run on a completely separate CPU core if available!

sapphire 
function heavyCalculation() {
    print("Thread ID " + Thread.currentId() + " is working...");
    var sum = 0;
    for (var i = 0; i < 10000000; i = i + 1) {
        sum = sum + i;
    }
    print("Thread finished with sum: " + sum);
}

// Spawns the thread in the background
var worker = Thread.spawn(heavyCalculation);

print("Main thread is still free to do other things!");

// Wait for the worker thread to finish before closing the app
worker.join();
> Main thread is still free to do other things!
> Thread ID 2 is working...
> Thread finished with sum: 49999995000000

Thread Safety and Mutexes

When multiple threads try to read and write to the same variable at the exact same time, you encounter a Race Condition, which causes data corruption. To solve this, Sapphire provides Mutex (Mutual Exclusion) objects to lock data access.

sapphire 
var sharedCounter = 0;
var lock = Mutex();

function incrementCounter() {
    for (var i = 0; i < 100; i = i + 1) {
        lock.acquire();
        // Now we safely own the counter
        sharedCounter = sharedCounter + 1;
        lock.release();
    }
}

var t1 = Thread.spawn(incrementCounter);
var t2 = Thread.spawn(incrementCounter);

t1.join();
t2.join();

print("Final Counter: " + sharedCounter);
> Final Counter: 200
