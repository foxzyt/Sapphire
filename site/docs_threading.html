Multi-threading

📖 What You Will Learn in This Chapter:
  • The difference between async (concurrency) and threading (parallelism)
  • How to spawn background threads with Thread.spawn()
  • How to wait for threads to finish with join()
  • What race conditions are and how to prevent them with Mutex
  • How to create CPU-heavy applications without freezing the UI

While async/await is perfect for I/O bound tasks (like waiting for the network), it still runs on a single thread. If you need to perform heavy mathematical calculations (CPU-bound tasks), you need true parallelism. Sapphire provides access to OS-level threads via the Thread class and the spawn keyword.

Async vs Threading

It's important to understand the difference:

  • Async/await: Runs multiple tasks on a single thread by switching between them when they wait. Great for I/O (network, files, timers).
  • Threading: Runs multiple tasks on separate CPU cores simultaneously. Great for CPU-heavy calculations (math, physics, image processing).

Creating and Spawning Threads

You can spawn a new thread by passing a function into Thread.spawn() or using the spawn keyword. The Virtual Machine will immediately schedule this function to run on a completely separate CPU core if available.

sapphire 
function heavyCalculation() {
    print("Thread working...");
    var sum = 0;
    for (var i = 0; i < 10000; i = i + 1) {
        sum = sum + i;
    }
    print("Thread sum: " + sum);
}

// Method 1: Using spawn keyword
print("Before spawn");
spawn heavyCalculation;
print("After spawn");

// Wait a bit so the thread can finish
var x = 0;
for (var i = 0; i < 500000; i = i + 1) {
    x = x + 1;
}
print("Done waiting. Main thread exiting.");
> Before spawn
> After spawn
> Thread working...
> Thread sum: 49995000
> Done waiting. Main thread exiting.

Notice that "After spawn" prints before the thread's output. This is because the thread runs in parallel — the main thread continues immediately without waiting for the spawned function to finish.

Using Thread.spawn() with join()

For more control, use Thread.spawn() which returns a thread object. You can call join() on it to wait for the thread to complete before continuing.

sapphire 
function work() {
    print("Thread ID " + Thread.currentId() + " is working...");
    var sum = 0;
    for (var i = 0; i < 10000000; i = i + 1) {
        sum = sum + i;
    }
    print("Thread finished with sum: " + sum);
}

// Spawns the thread and returns a handle
var worker = Thread.spawn(work);

print("Main thread is still free to do other things!");

// Wait for the worker thread to finish before closing
worker.join();
print("Worker has finished. Main thread exiting.");
> Main thread is still free to do other things!
> Thread ID 2 is working...
> Thread finished with sum: 49999995000000
> Worker has finished. Main thread exiting.

Thread Safety and Mutexes

When multiple threads try to read and write to the same variable at the exact same time, you encounter a Race Condition, which causes data corruption. To solve this, Sapphire provides Mutex (Mutual Exclusion) objects to lock data access. Only one thread can hold the lock at a time.

sapphire 
var sharedCounter = 0;
var lock = Mutex();

function incrementCounter() {
    for (var i = 0; i < 100; i = i + 1) {
        lock.acquire();
        // Now we safely own the counter
        sharedCounter = sharedCounter + 1;
        lock.release();
    }
}

var t1 = Thread.spawn(incrementCounter);
var t2 = Thread.spawn(incrementCounter);

t1.join();
t2.join();

print("Final Counter: " + sharedCounter);
> Final Counter: 200
⚠️ Important: Without the Mutex, the counter would likely end up with a value less than 200 because two threads might read the same value simultaneously, increment it, and write back the same result — effectively losing an increment. Always use lock.acquire() and lock.release() when sharing data between threads.

Overview — What You Learned

✅ Chapter Summary:
  • Async is for I/O-bound tasks (single-thread concurrency)
  • Threading is for CPU-bound tasks (true parallelism on multiple cores)
  • spawn keyword launches a function on a new thread: spawn myFunction;
  • Thread.spawn(function) returns a handle you can join() to wait for completion
  • Race conditions happen when multiple threads access shared data simultaneously
  • Mutex prevents race conditions: lock.acquire() / lock.release()
  • Always join() your threads before the program exits to ensure they finish
